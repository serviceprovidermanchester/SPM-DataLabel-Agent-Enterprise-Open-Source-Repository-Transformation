# Security Policy

## Supported Releases

SPManchester Private Limited actively maintains security updates and patches for the following versions of DataLabel:

| Release Version | Supported | Maintenance Status |
| :--- | :--- | :--- |
| 1.0.x | Yes | Active Security Maintenance |
| < 1.0.0 | No | End of Life |

---

## Reporting a Security Concern

We prioritize the safety, data integrity, and stability of our software and users. If you discover an issue or vulnerability within DataLabel:

1. **Do not disclose the issue publicly** via public GitHub issues, discussions, or social media channels.
2. **Submit details via email** directly to our security engineering team at:
   - **Email:** [info@spmanchester.com](mailto:info@spmanchester.com)
   - **Subject:** `[SECURITY] DataLabel Vulnerability Report`
3. Include the following details in your report to expedite triage:
   - Specific component or API endpoint affected.
   - Step-by-step reproduction instructions or a minimal proof of concept.
   - Potential impact on data integrity, authentication scoping, or service availability.

---

## Response and Disclosure Process

- **Acknowledgement:** We acknowledge receipt of vulnerability reports within 48 business hours.
- **Triage & Validation:** Our engineering team analyzes the reported vector and validates the severity.
- **Remediation & Patching:** A verified security patch is developed, tested through our automated test harness, and published.
- **Public Disclosure:** Once a fix is verified and deployed, a security advisory will be published with proper credit to the reporter.

Thank you for helping keep the open-source ecosystem secure.
